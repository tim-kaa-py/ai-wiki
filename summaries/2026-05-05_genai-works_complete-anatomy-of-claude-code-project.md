## TL;DR

A one-glance anatomy diagram of a Claude Code project: `CLAUDE.md` as **"Project Brain"**, `CLAUDE.local.md` as **"Personal Overrides"**, `.claude/` as the team-shared configuration root, plus `.mcp.json`, `.claudeignore`, and `plugins/`. The framing reaches for an OS analogy ("Claude is not a chatbot, but an OS for active development") and emphasizes hooks as the **deterministic** layer ("Cannot Hallucinate"). Useful as a mental map for newcomers; some specifics are inflated or non-standard (see flags below).

## Key Concepts

### "Project Brain" framing for `CLAUDE.md`

The infographic's most reusable framing: `CLAUDE.md` is the project's *brain* — auto-loaded every session, hierarchical (root → subdirectory → child on demand), and generated by `/init`. The metaphor is sharper than "instructions file" because it captures both the persistence and the cognition role.

### `CLAUDE.local.md` as "Personal Overrides"

The companion framing: gitignored, local env paths, debugging shortcuts, private prefs. Useful distinction for explaining the team-vs-individual split to people new to the harness.

### Hooks as the deterministic layer

The infographic's bolded claim: hooks "**Cannot Hallucinate**" — they are deterministic lifecycle events that the harness fires regardless of what the LLM decides. This framing is correct and worth borrowing: hooks are the part of the system that is *not* model-dependent. (See [Inaccuracies](#inaccuracies-and-questionable-specifics) on the count.)

### "OS for active development" framing

The closing claim: structured execution memory (shared task list, direct messaging, worktree isolation) makes Claude function as an OS for active development, not a chatbot. This is a thesis-level framing — same family as the "harness engineering" and "software factory" arguments already in the wiki, expressed as a single quotable line.

## Key Takeaways

1. **The visual anatomy is the whole product.** The value here is the single-page mental map of how the components fit together — `CLAUDE.md` + `.claude/{settings,skills,agents}` + `.mcp.json` + `.claudeignore` + `plugins/`. Use it for orientation, not configuration reference.
   **How to apply:** Show this diagram (or the verbatim file) to a teammate new to Claude Code as a 60-second orientation, then point them at the deeper wiki pages.

2. **Borrow the framings, not the specifics.** "Project Brain", "Personal Overrides", "Cannot Hallucinate", "OS for active development" — these are sharper than vanilla docs language and worth reusing in onboarding material.
   **How to apply:** When writing onboarding docs or talks, prefer these framings over neutral terms like "instruction file" or "configuration".

3. **Hooks "cannot hallucinate" is the right mental model for deterministic infrastructure.** Hooks fire on lifecycle events — they don't depend on the LLM agreeing.
   **How to apply:** When designing reliability-critical behavior (audit, blocking, security), express it as a hook, not as a CLAUDE.md instruction.

## Inaccuracies and Questionable Specifics

The infographic is broadly correct as a mental map but contains specifics that don't hold up to checking. Flagging them so they don't get repeated downstream:

- **"HOOKS — 25 Lifecycle Events"** — only **12** are listed (6 blocking + 6 informational). The "25" figure is either inflated, refers to a different counting (sub-events? combined with Claude Agent SDK callbacks?), or simply wrong. Trust the listed names, not the count. Cross-reference Anthropic's hooks documentation for the authoritative list.
- **`.claude/agent-memory/`** — shown as a direct subdirectory of `.claude/`. Persistent agent memory in this wiki's setup lives at `~/.claude/projects/<project-id>/memory/` (per the project's own auto-memory system). The infographic's path is non-standard or hypothetical.
- **`.claude/worktrees/`** — git worktrees live wherever git creates them, conventionally as sibling directories or under a `worktrees/` folder of the user's choosing — not as a fixed `.claude/worktrees/` subdirectory. The infographic conflates "Claude Code uses worktrees" with "worktrees live inside `.claude/`".
- **"1M-token context each"** — only the Opus 4.7 `[1m]` variant has a 1M context window today. Sonnet/Haiku agents do not get 1M each by default. The infographic implies a uniform property that isn't true.
- **"3 built-in agents: Explore (Haiku) + Plan + General"** — this part is accurate as of the current Claude Code (Opus 4.7 era).
- **Skills "Auto-invoked when task context matches description"** — accurate for description-based routing.
- **AGENT TEAMS labeled "Experimental"** — matches the experimental status of multi-agent coordination features in current Claude Code.
